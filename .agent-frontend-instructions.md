# Instructions Agent — Frontend Help.

But: fichier privé pour agents. Ne pas committer — déjà listé en `.gitignore`.

## Objectif

- Fournir à un agent ou à un futur assistant toutes les conventions, décisions et étapes de style front-end du projet `Help` afin de reproduire ou continuer le travail.

## Usage

- Lire ce fichier en premier lors d'une nouvelle conversation avec un agent sur ce repo.
- Suivre la checklist « Actions courantes » pour les modifications de styles.
- Exécuter `npm run build` pour valider les changements.

## Contexte technique

- Framework: Next.js (v16.x utilisé ici).
- UI: React (v19.x).
- CSS: Tailwind CSS (v4.x) via `src/app/globals.css` (entrée Tailwind avec `@import "tailwindcss"`).
- Scripts: `npm run build` → `next build`.

## Emplacement clés

- Racine projet: `src/`
- Fichier de références: `src/app/globals.css`
- Pages principales: `src/app/page.tsx`, `src/app/je-suis-une-ecole/page.tsx`
- Auth: `src/app/auth/login/page.tsx`, `src/app/auth/register/page.tsx`
- Composants: `src/components/*` (Navbar, Footer, home/\*)

## Conventions de style importantes

- Ne pas nommer une variable `white` (conflit possible avec Tailwind). Utiliser `--color-surface` pour la référence claire `#FFFDFF`.
- Les tokens couleur principaux existent dans `@theme` de `globals.css`:
  - `--color-ink` : couleur texte par défaut.
  - `--color-surface` : nouveau blanc de référence (#FFFDFF).
  - `--color-amber-*` et `--color-rose-*` : préserver les noms, valeurs opaques (comptées sur `#FFFDFF`).
- Il y a une utilité réutilisable `@utility rose-card-frame` (bord arrondi + bordure rose).

## Typographie

- Les tailles/poids par défaut sont définis dans `src/app/globals.css` :
  - `p` → font-size: 16px, line-height: 1.5
  - `h1` → font-size: 36px, font-weight: 700
  - `h2` → font-size: 24px, font-weight: 700
  - `h3` → font-size: 20px, font-weight: 700
- Règle stricte appliquée : ne pas utiliser de classes utilitaires Tailwind qui overrident les `text-*` (taille) et `font-*` (poids) sur `h`/`p`. Préférer utiliser les règles CSS globales dans `globals.css`.

## Actions courantes (checklist pour un agent)

1. Pour remplacer fonds proches du blanc → rechercher `bg-white` et couleurs hex proches → remplacer par `bg-surface` (token exposé dans `globals.css`).
2. Pour uniformiser texte principal → assurer `body` contient `text-ink` (déjà appliqué dans `src/app/layout.tsx`).
3. Pour couleurs variables Tailwind → vérifier que `@theme` définit bien les `--color-*` et que les classes Tailwind/utility correspondantes sont générées.
4. Pour presets réutilisables → vérifier `@utility rose-card-frame` et réutiliser `rose-card-frame` au lieu d'inlines.
5. Pour supprimer overrides de typo → enlever classes `text-...`, `sm:text-...`, `text-[...]`, `font-*` sur `h`/`p` et laisser `globals.css` gouverner.

## Validation

- Toujours lancer `npm run build` après modifications de styles.
- Vérifier qu'il n'y a pas de classes `bg-white` ou `text-(--color-ink)` résiduelles — rechercher dans `src/**`.

## Notes & décisions de conception

- Les couleurs `amber` et `rose` doivent conserver leurs noms même lorsqu'elles sont très claires.
- Les tokens translucides ont été convertis en valeurs opaques calculées contre `#FFFDFF` pour correspondre au rendu Figma.
- Préférence : centraliser styles de typo et couleurs dans `globals.css` plutôt que dans des utilitaires inline dispersés.

## Si tu relances un agent

- Si l'agent doit committer, s'assurer que `.agent-frontend-instructions.md` reste dans `.gitignore`.
