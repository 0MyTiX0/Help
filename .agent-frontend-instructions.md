# Instructions Agent — Frontend Help.

But: fichier privé pour agents. Ne pas committer — déjà listé en `.gitignore`.

## Objectif

- Fournir à un agent ou à un futur assistant toutes les conventions, décisions et étapes de style front-end du projet `Help` afin de reproduire ou continuer le travail.

## Usage

- Lire ce fichier en premier lors d'une nouvelle conversation avec un agent sur ce repo.
- Suivre la checklist « Actions courantes » pour les modifications de styles.
- Exécuter `npm run build` pour valider les changements.

## Contexte technique

- Framework: Next.js (v16.x utilisé ici).
- UI: React (v19.x).
- CSS: Tailwind CSS (v4.x) via `src/app/globals.css` (entrée Tailwind avec `@import "tailwindcss"`).
- Scripts: `npm run build` → `next build`.

- Racine projet: `src/`

## Conventions de style importantes

- Ne pas nommer une variable `white` (conflit possible avec Tailwind). Utiliser `--color-surface` pour la référence claire `#FFFDFF`.
- Les tokens couleur principaux existent dans `@theme` de `globals.css`:
  - `--color-ink` : couleur texte par défaut.
  - `--color-surface` : nouveau blanc de référence (#FFFDFF).
  - `--color-amber-*` et `--color-rose-*` : préserver les noms, valeurs opaques (comptées sur `#FFFDFF`).
- Il y a une utilité réutilisable `@utility rose-card-frame` (bord arrondi + bordure rose).

## Typographie

- Les tailles/poids par défaut sont définis dans `src/app/globals.css` :
  - `p` → font-size: 16px, line-height: 1.5
  - `h1` → font-size: 36px, font-weight: 700
  - `h2` → font-size: 24px, font-weight: 700
  - `h3` → font-size: 20px, font-weight: 700
- Règle stricte appliquée : ne pas utiliser de classes utilitaires Tailwind qui overrident les `text-*` (taille) et `font-*` (poids) sur `h`/`p`. Préférer utiliser les règles CSS globales dans `globals.css`.

## Actions courantes (checklist pour un agent)

1. Pour remplacer fonds proches du blanc → rechercher `bg-white` et couleurs hex proches → remplacer par `bg-surface` (token exposé dans `globals.css`).
2. Pour uniformiser texte principal → assurer `body` contient `text-ink` (déjà appliqué dans `src/app/layout.tsx`).
3. Pour couleurs variables Tailwind → vérifier que `@theme` définit bien les `--color-*` et que les classes Tailwind/utility correspondantes sont générées.
4. Pour presets réutilisables → vérifier `@utility rose-card-frame` et réutiliser `rose-card-frame` au lieu d'inlines.
5. Pour supprimer overrides de typo → enlever classes `text-...`, `sm:text-...`, `text-[...]`, `font-*` sur `h`/`p` et laisser `globals.css` gouverner.

## Boutons / CTAs (convention obligatoire)

Tous les boutons d'action principaux (CTA) du site suivent **un seul pattern** : pilule arrondie, fond `amber-100`, texte blanc, ombre amber, légère élévation au hover, **et obligatoirement un changement de couleur au hover**.

### Pattern de référence

```tsx
<Link
  href="..."
  className="inline-flex rounded-full bg-amber-100 px-6 py-3 text-white shadow-[0_10px_24px_rgba(255,176,71,0.25)] transition-all duration-200 hover:-translate-y-0.5 hover:brightness-95"
>
  <h3>Libellé du bouton →</h3>
</Link>
```

### Règles strictes

1. **Le libellé du bouton est toujours dans une balise `<h3>`** (ou `<h2>` pour les CTA héros plus grands). Jamais de `<span>` ou texte nu avec `text-sm font-medium` — la typo est régie par `globals.css`.
2. **Fond `bg-amber-100`** (= `#ffb047`). **Ne JAMAIS utiliser** `bg-orange-400`, `bg-orange-500`, `bg-yellow-*` ou autres jaunes/oranges Tailwind par défaut. Le jaune correct est uniquement le token `amber-100` défini dans `globals.css`.
3. **Texte `text-white`** (jamais `text-black` sur fond amber).
4. **Ombre** : `shadow-[0_10px_24px_rgba(255,176,71,0.25)]` (variantes acceptées : `0.20`, `0.32` selon la taille).
5. **Hover OBLIGATOIRE avec changement visuel de couleur** : ajouter `hover:brightness-95` (ou `hover:brightness-90` pour un effet plus marqué). `hover:-translate-y-0.5` seul ne suffit pas — un changement de teinte/luminosité est requis. La palette `amber` n'a pas de ton plus foncé que `amber-100`, donc on utilise `brightness-*` ou `opacity-*` au lieu d'un token `hover:bg-amber-*`.
6. **Transition** : préférer `transition-all duration-200` pour englober transform + brightness simultanément.
7. **Forme** : toujours `rounded-full` (pilule).
8. **Flèche** : si présente, inline dans le `<h3>` sous forme de caractère (`→`) plutôt qu'un SVG séparé, pour rester cohérent avec les CTA de `je-suis-une-ecole`.

### Boutons secondaires / navigation carrousel

Pour les boutons rond/icône (pagination, fermeture, etc.) :

```tsx
className =
  "flex h-11 w-11 items-center justify-center rounded-full border border-rose-20 bg-surface text-rose-100 transition hover:-translate-y-0.5 hover:bg-rose-10";
```

Utilise les tokens `rose-*` et `amber-*` du `@theme` — **jamais** `rose-200`, `rose-700`, `amber-50`, etc. (ces classes Tailwind par défaut n'existent pas dans notre palette personnalisée).

### Cohérence couleurs

- Accent rose (titres décoratifs, numérotation, surlignage) → `text-rose-100`
- Fond doux secondaire (sections cards) → `bg-amber-10` ou `bg-rose-10`
- Bordure rose → `border-rose-20` ou utiliser `rose-card-frame`
- Texte secondaire → laisser hériter (`text-ink`) ou utiliser `text-rose-100` pour accents

## Routes dynamiques — slugs au lieu d'UUID

Pour toute page dynamique exposée à l'utilisateur (catégories, sous-catégories, articles, etc.), **l'URL doit utiliser un slug lisible** dérivé du `name`, jamais l'UUID brut.

- Helper centralisé : `src/lib/slug.ts` exporte `slugify(name)`.
- Convention de dossier App Router : `app/categories/[slug]/page.tsx` (et non `[categoryId]`).
- Côté serveur : récupérer toutes les entités candidates puis matcher par `slugify(entity.name) === slug`. Si pas de correspondance → `notFound()`.
- Si deux entités produisent le même slug : ajouter manuellement un champ `slug` unique en base (à envisager si collisions).

## Notes & décisions de conception

- Les couleurs `amber` et `rose` doivent conserver leurs noms même lorsqu'elles sont très claires.
- Les tokens translucides ont été convertis en valeurs opaques calculées contre `#FFFDFF` pour correspondre au rendu Figma.
- Préférence : centraliser styles de typo et couleurs dans `globals.css` plutôt que dans des utilitaires inline dispersés.
